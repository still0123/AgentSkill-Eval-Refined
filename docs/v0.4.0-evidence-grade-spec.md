# AgentSkill-Eval Refined v0.4.0 Evidence-Grade Spec

## Mission

v0.4.0 upgrades the project from portfolio-grade demonstration to evidence-grade Skill
evaluation, optimization, and release. A negative, no-gain, regression, or invalid result is a
valid deliverable when its semantics and evidence are correct.

## Priority

1. P0 evaluation semantics.
2. P0 evidence completeness and run isolation.
3. P1 benchmark breadth and oracle quality.
4. P1 statistics, optimization depth, and a second Agent Runtime.
5. P2 Dashboard, README, release, and interview material.
6. P3 optional research extensions.

No MCP, Memory/RAG, FastAPI, Redis, Kubernetes, or unrelated platform expansion is allowed before
both P0 gates pass.

## P0 Evaluation Semantics

- `PASS`, task `FAIL`, and infrastructure `INVALID` remain distinct through every aggregation.
- A pair containing any `INVALID` observation is never a tie, win, loss, or confirmation.
- Search, regression, confirmation, locked test, promotion, Dashboard, and release use the same
  decision vocabulary.
- Assignment-based and valid-only estimands remain separately named.
- Zero gain cannot be promoted as improvement.

## P0 Evidence and Isolation

- Every claim binds Skill, DatasetVersion, Runner, Agent, Runtime, config, input, output, Trace,
  grader, and report hashes.
- Audit bundles verify exact file sets and reject missing, extra, modified, or path-escaping files.
- Adaptive splits cannot read confirmation or locked-test content.
- A one-shot locked test remains consumed after failure.
- Simulated, observed-Agent, environment-error, and excluded evidence cannot be aggregated.
- Third parties can verify public evidence offline without credentials or source checkout state.

## P1 Benchmark and Oracle

- Add independent repositories and defect families before adding more same-family variants.
- Every Case requires before-fail, after-pass, mutation-fail, and distinct-alternative-pass checks.
- Dataset selection never uses Agent scores.
- Report repository, fork lineage, patch family, and contamination risk.

## P1 Statistics, Optimization, and Runtime

- Report W/T/L/INVALID, valid-pair ratio, group-weighted gain, confidence interval, token overhead,
  latency, and cost when observed.
- Optimization proposals may edit structured workflow sections, not only append one sentence.
- A second Agent Runtime must use the same frozen input and evidence contracts.
- Paid APIs and hosted runners remain forbidden by project policy.

## P2 Presentation

- Dashboard labels evidence class, estimand, split, invalid count, and claim limit.
- README separates supported claims, negative results, and unsupported extrapolations.
- v0.4.0 release includes clean-room artifacts, SHA-256, provenance, and offline verification.

## Completion

Core release requires P0 completion, local quality gates, clean-room install, deterministic
evidence verification, and no unresolved P0/P1 correctness defect. P2/P3 work cannot delay core
closure.
