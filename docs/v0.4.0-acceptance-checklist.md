# v0.4.0 Evidence-Grade Acceptance Checklist

## P0 Evaluation Correctness

- [x] Final evaluation preserves `INVALID` separately from W/T/L.
- [x] Any invalid final pair blocks confirmation and promotion.
- [x] Search and regression apply the same invalid semantics.
- [x] Assignment-based and valid-only estimands are labeled and tested.
- [x] Zero-gain and tie-negative results cannot claim improvement.

## P0 Evidence and Isolation

- [x] Evidence lineage binds all executable and data identities.
- [x] Audit bundles reject missing, extra, modified, and unsafe paths.
- [x] Search cannot access confirmation or locked-test content.
- [x] Locked-test receipt survives failed execution.
- [x] Evidence classes cannot be mixed.
- [x] Offline third-party verification passes in a clean environment.

## P1 Benchmark and Oracle

- [x] At least one new repository family is published.
- [x] Every new Case passes four-way oracle validation.
- [x] Repository, fork, patch-family, and contamination metadata are complete.
- [x] Agent scores do not affect Case selection.

## P1 Statistics, Optimization, and Runtime

- [x] Reports include W/T/L/INVALID and valid-pair ratio.
- [x] Group-weighted intervals and efficiency metrics are reproducible.
- [ ] Optimization supports a structured change beyond prompt suffix append.
- [x] A second Runtime passes the same evidence contract.

## P2 Release and Presentation

- [ ] Dashboard labels evidence class, estimand, split, and invalid count.
- [ ] README states positive, negative, no-gain, and regression results.
- [ ] v0.4.0 wheel and sdist pass clean-room verification.
- [ ] Release SHA-256 and provenance verify after download.

## Open-Source Borrowing

- [ ] Every consulted repository is recorded in `open-source-design-log.md`.
- [ ] License, adopted pattern, rejected alternatives, adaptation, and tests are recorded.
